### Unresolved checks

Twenty failing test cases appear in both full runs. They include missing local
`anthropic` dependency, PowerShell execution-policy restrictions in cancellation tests,
Windows bridge integration failures, demo-data expectations, access expectations,
archive text and a date-sensitive future-quarter fixture. Shared failure names establish
reproduction on the baseline; they do not establish the root cause of every failure.

Two failure names occur only in the current full run:

- `LegacyMigrationTests.test_legacy_values_audit_snapshots_and_explicit_link`: migrating
  a historical ready order fails `wo_ready_requires_filing_confirmation`. A Windows
  temporary-database cleanup lock follows the migration error. **Fresh test database
  creation passes, but upgrades with legacy ready orders need investigation before
  applying these migrations to another environment.** Do not bypass the constraint or
  change historical confirmations merely to make migration succeed.
- `WindowsBridgeTests.test_dashboard_release_clears_only_matching_running_journal`:
  the expected recovery response is false during the full run and an isolated rerun
  (1 test, 1 failure). Treat this worker
  recovery path as unresolved until reproduced and diagnosed.

The baseline additionally failed `SampleFormTests.test_pdf_is_draft_and_does_not_create_work_order`,
which passed in the current full run. Differences in test count reflect added coverage;
they do not mean all new behavior has end-to-end verification.
