The resend flow reads the confirmation text before clicking OK, distinguishes
NORMAL and RESEND, skips normal-only TOSA/close steps on resend, and retains
the approval, form, period, saved-file identity and full-screen evidence checks.
Success-message selectors accept `Submit Successful` for both punctuation variants.
FAILED_SYSTEM is not proof that no submission occurred: inspect the attempt,
dialog and evidence before authorizing any retry.

## Versioned assets and deployment

- `worker/Initialize-1601EQResend.ps1`: validates the approved XML location and
  status, requires one temporary eBIRForms runtime, and returns NORMAL, RESEND or
  BLOCKED. Already-submitted flag 1 is blocked; flag 2 uses the repair helper.
- `worker/Repair-1601EQResendScript.ps1`: accepts only the known 1601EQ script
  SHA-256, preserves byte encoding, backs up before patching, recognizes an
  already patched file and refuses unknown versions or a mismatched backup.
- `docs/pad-actions/*.actions.txt`: action-only snapshots, without the embedded
  screenshots and UI repositories. They are review/reference assets, **not
  standalone importable flows**. Their UI element references require the original
  flow's repository. Preserve literal LF line breaks in the 1601EQ snapshot.

Copy both PowerShell helpers together into `C:\TaxAutomation` when deploying
this flow on another worker. A Git pull does not install helpers or update PAD.
Use the restricted full export and check its selectors and inputs in Designer;
save only with no errors. Do not run a child submission flow directly. Use the
parent worker only for a separately approved attempt after checking existing
submission evidence. No flows were run for this Git/documentation update.

The workaround targets the observed script hash, not every eBIRForms release.
An unknown runtime must be investigated; do not remove the hash guard. Restore
the backed-up flow and matching helper deployment if rolling back. Do not alter
saved XML status to manufacture a retry.
